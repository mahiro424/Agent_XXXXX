# 设计系统文档：Agent_XXXXX

> UI 模式：`spec-driven`（规范驱动 UI）

## 1. 概览与创意北极星

### 创意北极星：「桌面上的安静助手」

Agent_XXXXX 是一款 Windows 优先的桌面 Agent 客户端。它的气质不是“科技监控台”，而是“桌面上的安静助手”：浅色、留白、低饱和、少装饰，让任务本身成为视觉中心。我们刻意避免拥挤的工具栏、高对比色块和花哨动效，因为产品的核心是让用户理解 Agent 正在做什么，而不是让界面抢走注意力。

与常见 AI 聊天应用的区别在于：这里不只是“打字 → 出文本”，而是“任务 → 计划 → 审批 → 执行 → 验证”。因此设计上要给计划、证据和状态变化留出清晰的节奏：信息按“现在发生了什么”排序，而不是按功能堆叠。

参考图确定了首屏方向：左侧为会话/案例/定时任务/技能/连接器导航，主区域为欢迎区与任务输入框，底部为工作区/权限/模型状态。整体用大留白制造呼吸感，用少量近黑色强调按钮建立唯一视觉焦点。

### 打破模板感的方式

- 用大量留白代替分割线，让层级靠空间而非线框表达。
- 卡片采用低对比灰底与细圆角，避免投影泛滥。
- 强调按钮只用于“生成方案”“批准执行”等关键动作，一次只出现一个主行动点。
- 状态用“文字 + 图标 + 轻色块”共同表达，不单独依赖颜色。

## 2. 色彩与表面架构

整体采用“中性灰基底 + 单一强调色”的策略：灰色承载信息和结构，强调色只标记关键动作与选中态。色板向浅色、低饱和、近黑文字靠拢，保证在大多数 Windows 屏幕和深浅主题下都有足够对比度。

### 无描边规则

**明确指令：** 禁止使用 1px 实线边框作为常规区块分隔。区块之间优先用背景色阶（`surface-card` vs `surface-base`）、间距和留白区分；必须表达分隔时才使用低透明度的幽灵描边（详见第 4 节 `ghost-border`）。

### 表面层级与嵌套

- `surface-base`：应用底色，`#F9FAFB`；
- `surface-card`：卡片/模块，`#FFFFFF`；
- `surface-muted`：次级填充，`#F3F4F6`；
- `surface-modal`：浮层/弹窗，`#FFFFFF` + 弱阴影；
- 嵌套时保持“纸面在灰底之上”，最多两层卡片，避免卡片套卡片。

### 玻璃与渐变规则（若适用）

暂不适用，跳过。V1 不使用毛玻璃、大面积渐变或纹理作为主要视觉语言；强调色渐变仅在按钮等单一原语上以低强度使用。

## 3. 字体：编辑感版式

标题和正文采用同一套无衬线体系，通过字重和字号建立层级，而不是混用多种字体族。中文优先使用系统默认中文字体，保证 Windows 原生渲染稳定。

### 字号阶梯（品牌板须可视化）

| 角色 | 字体族 | 用途 | 样例层级 |
|------|--------|------|---------|
| 标题 | 系统无衬线（`Segoe UI`，中文回退 `Microsoft YaHei`） | 欢迎语、页面主标题 | 28–32px / 600 |
| 正文 | 系统无衬线 | 正文、说明、按钮文字 | 14–16px / 400–500 |
| 标签 | 系统无衬线 | 标签、辅助说明、状态 | 12px / 500 |

### 信息层级

标题与正文通过字号和字重区分；标签用 `neutral-600` 降低视觉重量；关键数字或状态可用主色强调。避免在同一行使用超过两种字重。

### 字体实现约束

纯桌面 WebView 环境，无自定义字体加载限制；统一使用系统字体栈，避免安装字体依赖。

| 触点 | 稿面字体 | 实现字体 / fallback 栈 | 加载策略 |
|------|---------|----------------------|---------|
| Windows 桌面 | Segoe UI / Microsoft YaHei | `system-ui, "Segoe UI", "Microsoft YaHei", sans-serif` | 系统字体，无需加载 |

## 4. 层级与深度

层级主要通过色调叠层和留白建立，不使用粗线框。浮动元素（弹窗、下拉、托盘）使用克制的环境阴影，避免纯黑硬阴影。

- **叠层原则：** `surface-muted` 之上的 `surface-card` 表示可交互区块；`surface-card` 之上的 `surface-modal` 表示临时浮层。叠层不超过两层。
- **环境阴影：** 浮层阴影使用 `rgba(17,17,17,0.08)`，模糊 16–24px，偏移 0–2px；不使用纯黑 `#000` 硬阴影。
- **幽灵描边兜底：** 必须描边时使用 `neutral-500 @ 18%`，Token 名 `ghost-border`，禁止 1px 实线黑边。

## 5. 组件

本节省略具体页面和业务字段，只定义可复用通用原语。所有叠色均引用第 4 节 Token；单次不复用的叠色直接写 HEX。

### 按钮与交互（品牌板须可视化）
- **主按钮：** 背景 `primary` `#1E6FFF`，文字 `#FFFFFF`，圆角 8px，内边距 10px×16px；悬停加深至 `#1450C4`，按下再加深；禁用 `neutral-300` 背景 + `neutral-500` 文字。
- **次按钮：** 背景 `surface-card`，文字 `neutral-800`，带 `ghost-border`；悬停背景 `neutral-tint-8`。
- **描边按钮：** 背景透明，1px `ghost-border`，文字 `neutral-700`；悬停 `neutral-tint-8`。
- **文字按钮：** 无背景无边框，文字 `neutral-700`；悬停 `primary-tint-8` 底。
- **反色按钮：** 深色面上使用；背景 `#FFFFFF`，文字 `#111111`；悬停 `#F3F4F6`。

### 输入与表单
- 默认态：背景 `surface-card`，`ghost-border`，圆角 8px，内边距 8px×12px，文字 `neutral-800`。
- 聚焦态：`primary-tint-15` 外发光 + `primary` 边框。
- 错误态：边框和提示文字引用 `semantic-error`；背景 `error-tint-10`。

### 卡片容器
- 背景 `surface-card`，圆角 10px，内边距 16px，无阴影或轻阴影；不使用硬边框。

### 列表行
- 行高 44–52px，行间距 0；行内使用弱分隔或靠间距区分；悬停 `neutral-tint-8`，选中 `primary-tint-8` + 左侧 2px `primary` 指示条。

### 导航
- 桌面端以左侧导航为形态；菜单项文字 `neutral-600`，选中态文字 `neutral-900` + 背景 `primary-tint-8`；图标 20px，选中态使用 `primary`。

### 搜索框
- 输入框复用“输入与表单”默认态；下拉结果浮层使用 `surface-modal` 卡片 + 环境阴影；无全局搜索时可跳过具体业务占位符。

### 状态徽章
- 形态：padding 4px×10px，圆角 999px，字号 12px；样例：成功徽章背景 `success-tint-10`、文字 `semantic-success`；错误徽章背景 `error-tint-10`、文字 `semantic-error`。

### 图标按钮
- 尺寸 32px，图标 18–20px，描边 1.5px；默认 `neutral-500`，悬停 `neutral-tint-8` 底，选中 `primary-tint-8` 底 + `primary` 图标。底栏/侧栏图标选中态与此一致。

### 空状态
- 居中布局：图标 48–64px，`neutral-400`；主文案 14px `neutral-600`，辅助文案 12px `neutral-500`；可选 CTA 使用次按钮或主按钮变体。

### Loading（若适用）
- 骨架屏：`neutral-100` 底 + 呼吸闪烁；spinner：24px，`primary` 描边；不适用时跳过。

## 6. 宜忌

### 应当：
- **应当** 用留白和背景色阶区分区块，而不是依赖描边。
- **应当** 让关键动作一次只出现一个主按钮。
- **应当** 用“文字 + 图标 + 轻色块”共同表达状态，不只靠颜色。
- **应当** 保持界面浅色、低饱和，让任务内容成为视觉中心。
- **应当** 在浮层中使用克制的环境阴影，避免纯黑硬阴影。

### 禁止：
- **禁止** 使用 1px 实线边框作为常规区块分隔。
- **禁止** 在同一行混用超过两种字重。
- **禁止** 使用大面积渐变、毛玻璃或纹理作为主要视觉语言。
- **禁止** 用颜色单独表达错误、成功、警告或信息状态。
- **禁止** 在无授权情况下让界面暗示 Agent 正在后台操作桌面。
