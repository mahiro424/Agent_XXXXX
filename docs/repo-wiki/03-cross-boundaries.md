# 03 跨边界交互与安全模型

Agent_XXXXX 在架构上严格划分了三层安全与进程边界。

---

## 边界拓扑

```text
┌──────────────────────────────────────────────────────────┐
│ 1. 渲染进程 (Chromium)                                   │
│    UI DOM / 用户交互 / Markdown 渲染                      │
└──────────────────────────┬───────────────────────────────┘
                           │ IPC (ContextBridge 白名单)
┌──────────────────────────▼───────────────────────────────┐
│ 2. Electron 主进程 (Node.js) & DesktopSession            │
│    AppServer / RuntimeEngine / 本地安全沙箱               │
└──────────────┬───────────────────────────┬───────────────┘
               │ 安全子进程管道 (stdio)       │ HTTPS Bearer Token
┌──────────────▼────────────┐ ┌────────────▼───────────────┐
│ 3. 外部 MCP 服务与脚本进程  │ │ 4. 大模型云端服务商 (DeepSeek)│
│    计算、外部数据库等       │ │    思考推理、参数生成          │
└───────────────────────────┘ └────────────────────────────┘
```

---

## 安全隔离核心准则

1. **渲染进程零特权**：Renderer 无法直接调用 `fs`、`child_process` 或发送任意网络请求；
2. **工作区物理越界拦截**：沙箱严格限制在用户选中的工作区绝对目录中，任何试图使用 `../` 或反斜杠穿越到系统盘根目录的操作均会被拦截报错；
3. **敏感密钥保护**：API Key 仅存储于本地用户专属配置文件中，绝不上传至任何第三方分析或遥测平台。
