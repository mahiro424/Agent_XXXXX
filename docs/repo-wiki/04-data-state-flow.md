# 04 数据流与状态持久化

本文档阐述系统内核心数据实体与持久化机制。

---

## 1. 核心实体定义

- **Thread**：代表一个独立的问题或任务会话上下文，拥有独立的工作区路径与配置；
- **Turn**：代表一次用户与智能体的交互轮次，包含用户输入、思考过程、工具调用与最终回复；
- **Plan**：大模型对复杂任务拆解出的执行计划步骤（包含风险等级与审批要求）；
- **RuntimeEvent**：结构化事件流（如 `turn.started`、`tool.executed`、`artifact.verified`）。

## 2. JSONL 事件日志与崩溃恢复

系统所有事件均通过追加写模式保存在持久化 JSONL 日志中。当系统意外断电或被强制终止后，重启系统即可重新读取事件序列，准确将状态恢复至断点处，并在遇到未完成的不确定操作时锁定在 `RECONCILIATION_REQUIRED`，防止自动重放产生破坏性写入。
